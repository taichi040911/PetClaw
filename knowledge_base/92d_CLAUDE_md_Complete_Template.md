## PetClawプロジェクト概要

### ビジョン

PetClaw は、**AI × ペットシミュレーション**のゲームです。

プレイヤーは「ペット」を育てます。ペットは AI で動いていて、以下の特徴があります：

- **生き死に** — ペットは時間とともに老いて、最終的に死ぬ。その過程が感動的。
- **独自言語進化** — ペット同士が会話する。その中で新しい言葉が自然に生まれて、広がっていく。
- **交配** — ペット同士が愛し合い、子どもが生まれる。子は親の特徴（見た目、言葉）を受け継ぐ。

### コア原理（第一原理）

この5つが、すべての判断基準です。迷ったら、これに立ち戻ってください。

1. **P1: 一貫性 × 記憶 = 愛着**
   - プレイヤーがペットに愛着を持つ = ペットの行動が一貫していて、プレイヤーの行動を「覚えている」感じがする

2. **P2: API Cost is Physics**
   - Claude API の呼び出しはお金がかかる。無駄な呼び出しはしない。賢く設計する。

3. **P3: Player Agency**
   - プレイヤーが「自分の判断でゲームが変わる」と感じることが大事。
   - AI に全部決めてもらう感覚は避ける。

4. **P4: 10秒フック**
   - ゲームを始めてから10秒以内に「やってみたい」と思わせる。
   - つまり、難しい説明や導入は最小限。

5. **P5: Complexity is Debt**
   - 複雑さは「借金」と同じ。いずれ返す必要がある。
   - シンプルな設計を心がける。

## コーディング規約（簡易版）

### GDScript（Godot の言語）について

プロジェクトはすべて GDScript で書かれています。以下の規約を守ります：

#### 1. クラス名を宣言する

```gdscript
class_name PetAI
extends Node
```

「このファイルは PetAI というクラス」と最初に宣言します。

#### 2. 型を明確に書く

```gdscript
var health: int = 100
var name: String = "Tama"
func heal(amount: int) -> void:
    health += amount
```

「これは整数です」「これは文字列です」と明確に書きます。コンピュータが間違いを見つけやすくなります。

#### 3. ゲーム全体の設定は GameManager を通す

```gdscript
var game_manager: GameManager = GameManager.instance
game_manager.save_data()
```

ゲーム全体で共有する情報（セーブデータなど）には、`GameManager` というまとめ役を通してアクセスします。

#### 4. セーブ・ロード対応

新しい機能を作ったら、以下を必ず実装します：

```gdscript
func to_dict() -> Dictionary:
    return {
        "health": health,
        "name": name
    }

func from_dict(data: Dictionary) -> void:
    health = data.get("health", 100)
    name = data.get("name", "")
```

「この情報はどうやって保存・復元するか」を定義します。

#### 5. シグナル（信号）で疎結合に

```gdscript
signal health_changed(new_health: int)

func take_damage(damage: int) -> void:
    health -= damage
    health_changed.emit(health)  # 変わったことを知らせる
```

「何かが変わった」を、別のモジュールに知らせます。直接いじらない。

## セーブ・ロードシステム

ゲームの保存の仕組みです。**この仕組みを理解しておくと、デバッグが早くなります。**

### どうやって保存するか？

1. **ゲーム内の情報を Dictionary（辞書）に変換**
   ```gdscript
   var pet_data = pet.to_dict()  # ペット情報を文字列化
   ```

2. **JSON ファイルに書き込む**
   ```gdscript
   var json = JSON.stringify(pet_data)
   file.store_string(json)  # "savegame.json" に保存
   ```

3. **後で読み込むときは逆**
   ```gdscript
   var json_text = file.get_as_text()
   var loaded_data = JSON.parse_string(json_text)
   pet.from_dict(loaded_data)  # 復元
   ```

### どこに保存するか？

- **GameManager の save_data** — ゲーム全体の設定
- **各システムの to_dict()** — 個別モジュールのデータ

例：
```gdscript
# GameManager.gd
var save_data = {
    "pets": [],
    "evolution": evolution_mechanics.to_dict(),  # 進化システム
    "language": pet_autonomy_system.to_dict(),    # 言語システム
    "timestamp": Time.get_ticks_msec()
}
```

## エラーが出たときの対処法

### こんなエラーが出た → こうしてください

| エラー | 原因 | 対策 |
|--------|------|------|
| `error: Identifier 'GameManager' not found` | GameManager がプロジェクトに登録されていない | `/implement GameManager クラスを作成` |
| `error: _process() is not defined` | アンダースコア付き関数の綴り間違い | エラーメッセージ全文をコピーしてAIに見せる |
| セーブができない | to_dict() が実装されていない | その機能に `to_dict()` を追加する |
| ゲームが遅い | API呼び出しが多すぎる | P2 (API Cost is Physics) を思い出す |

### 一般的な相談フロー

1. **エラーメッセージ全文をコピー**
   ```
   「こんなエラーが出ました：
   error: Undefined reference to 'PetAI' in 'main.gd:5'
   」
   ```

2. **何をしようとしていたか説明**
   ```
   「ペットの AI を作ろうとしていました」
   ```

3. **AI が原因と対策を提案**
   ```
   「原因：PetAI クラスが main.gd で参照されているが、まだ作られていない
   対策：/implement で PetAI.gd を作成してください」
   ```

4. **確認後、実行**
   ```
   「わかりました。作成してください」
   ```

## よくある質問（FAQ）

### Q: 一度に複数の機能を頼めますか？

A: はい、ただし「小さいタスク × 複数」にしてください。

```
NG: 「ペットシステム全体を作ってください」
OK: 「PetAI.gd の _process() メソッドを実装してください」
    「次に、ペットの体力システムを実装してください」
```

### Q: 書いたコードが気に入りません。全部書き直してもいい？

A: はい、`/review` でフィードバックをもらって、`/iterate` で改善してください。

### Q: デバッグして欲しいです。何をしたらいい？

A: `/debug` で以下を教えてください：
- どんな動作をしたか
- 何が起きたか（予期しない動作）
- エラーメッセージがあれば全文

### Q: Ralph Loop とは何ですか？

A: 「同じ改善テーマを何度も試行錯誤するエージェント」です。

例：言語進化が遅い → 何度も試す → 最良の案を提案

### Q: セーブ・ロードが壊れました。

A: 以下の順で確認してください：
1. エラーメッセージをコピー
2. `/debug` で相談
3. 該当ファイルの `to_dict()` と `from_dict()` を確認
4. GameManager.gd の save_data に登録されているか確認
