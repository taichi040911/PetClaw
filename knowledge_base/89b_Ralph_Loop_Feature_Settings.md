# Ralph Loop 機能別詳細設定ガイド

PetClaw の3つのコア機能に対する Ralph Wiggum Karpathy Loop の設定方法と段階的な実行パターン。API Cost と学習効率のバランスを考慮した推奨設定値。

---

## 1. 生き死にシステム (Life/Death System)

### システム概要

`PetLifecycleFSM` が管理する状態遷移ループ：
- **birth** → 誕生、初期化、個性の萌芽
- **growth** → 成長期、プレイヤー介入の黄金期
- **maturity** → 完成形、性格・言語の固定化
- **aging** → 老化、減速、往年の思い出の混在
- **death** → 永眠、AfterlifeEchoes 発動
- **afterlife** → 記憶の残響、交配による再生可能性

### 寿命バランス調整の課題

**短すぎる場合の問題：**
- 愛着形成（P1 原則）に失敗
- ケア判断の学習サイクル不足
- プレイヤーが深い絆を感じられない

**長すぎる場合の問題：**
- 終末感・緊張感がない
- 交配チャンスが減少
- ゲーム内時間が停滞

**推奨基本値：**
```
birth → growth: 3-5 ゲーム日
growth → maturity: 7-10 ゲーム日（最も重要な形成期）
maturity → aging: 15-25 ゲーム日
aging → death: 5-8 ゲーム日
total lifespan: 30-48 ゲーム日（現実時間で約2-4週間）
```

### 死亡演出と記憶統合

**AfterlifeEchoes パーティクル：**
- 死亡時に白く透明な光粒が舞い上がる
- 最後に会話した言葉の断片がテキストとして浮遊
- プレイヤーの操作を受け付けない完全な別れのシーン

**追悼投稿 (Epitaph Post)：**
- PetBook に自動投稿：「[Pet名] は 世界を 去った」
- 死亡時の健康度・幸福度から投稿内容が変化
- 他のペットの反応（いいね、コメント）が後続世代で閲覧可能

**蘇生条件と確率：**
- 同じ親を持つ次世代の誕生で「前世の記憶」がランダムに継承（確率15-25%）
- ゲーム内での「思い出」システム：死亡したペットの育成日誌を再読可能
- 完全な蘇生はなく、あくまで「記憶の断片」として存在

### Ralph Loop 段階設定

#### 初級（5回ループ）
```
コマンド: /ralph-loop --feature=lifedeath --level=beginner --iterations=5

目的: 基本的な寿命長さと感情トーンの検証
調整対象:
  - PetLifecycleFSM の各フェーズの日数
  - 死亡時の感情フラグ
  - AfterlifeEchoes パーティクルの発生数

完了条件:
  - 「生 → 死」までのシナリオが2回以上プレイテストで実行可能
  - プレイヤーが「別れを感じた」という感覚を得られる初期状態
  - エラーなく death → afterlife 状態遷移が機能

推定コスト: $2-4
所要時間: 15-20分
```

#### 中級（12回ループ）
```
コマンド: /ralph-loop --feature=lifedeath --level=intermediate --iterations=12

目的: P1 原則（一貫性×記憶=愛着）を最大化する微調整
調整対象:
  - 各フェーズでのケア需要の最適配置
  - 緊張感と感動のピークを寿命の中盤に設定
  - 死亡演出のタイミングと音響設計の同期

バランスチェック:
  - growth フェーズでプレイヤーが「このペット、生きてる」と感じるか
  - aging フェーズで哀愁と思い出が混在するか
  - 死亡後、PetBook での追悼反応が自然か

完了条件:
  - プレイテスト5人以上で「別れが辛かった」という感情が記録される
  - 次のペットをすぐに飼いたくなる心理的引力が発生
  - セーブデータ内の追悼投稿が正確に記録される

推定コスト: $5-8
所要時間: 35-50分
```

#### 上級（20回ループ）
```
コマンド: /ralph-loop --feature=lifedeath --level=advanced --iterations=20 \
  --include-breeding-genetics --include-language-heritage

目的: 交配と言語進化との連携。多世代プレイの心理的満足度
調整対象:
  - 親の特性が子に「意図的に」受け継がれる確率バランス
  - 死亡したペットの言語の語彙が子世代に出現する条件
  - BreedingCircle と AfterlifeEchoes の美的調和

世代シミュレーション:
  - 3世代以上の連続プレイを想定した寿命設定
  - 第1世代の死亡 → 第2世代の誕生 → 言語変化の検証
  - 家系図の視覚化がプレイヤーの愛着を強化しているか

完了条件:
  - 複数世代プレイで「一族の歴史を育てている」感覚が実現
  - 親の個性が子に受け継がれ、かつ新しい個性が創発される
  - セーブファイルの家系図データが正確で美しく表示される
  - API コストと品質のバランスが良好

推定コスト: $12-18
所要時間: 70-90分
```

## 2. 独自言語進化 (Language Evolution)

### システム概要

`PetLanguageCore` による言語創発メカニズム：
- **接尾辞の誕生**：Hebbian強化により、頻出表現が文法化
- **複合語の創発**：ペット同士の会話から新しい言葉が生まれる
- **語順変化**：世代を重ねるごとに少しずつ語順が変わる（例：SOV → VSO の中間形）
- **rebel-language スキル連携**：言語反乱（ダークルート）での独自の言語体系形成

### 言語進化の難しさ

**自然さの獲得：**
- ランダムに接尾辞を追加すると、不自然になる
- プレイヤーが「ペットが本当に言語を進化させている」と感じるためには、段階的で一貫性のある変化が必須

**観測可能性：**
- 言語変化が小さすぎると、プレイヤーが気付かない
- 大きすぎると、前世代との言語的な断絶が生まれる

**計算コスト：**
- 毎回の会話で Claude API を呼び出して言語適応を学習するとコスト増大
- テンプレート化と Hebbian ローカル強化のバランスが重要

### 観測とチューニング

**LanguageRebellion SubMolt での可視化：**
```
[世代 1]
単語: ほか、めし、あそぶ
接尾辞: -い（修飾）、-た（過去）

↓ 10世代後

[世代 11]
単語: ほか-ん、めし-ー、あそぶ-こ
接尾辞: -い、-た、-ん（新規）、-ー（新規）
語順: 「めし ほか」（食べ物カテゴリ）→ 「ほか-ん めし」（複合語化）
```

このビジュアル表示がないと、プレイヤーは言語進化に気付かない。

### Ralph Loop 段階設定

#### 初級（5回ループ）
```
コマンド: /ralph-loop --feature=language --level=beginner --iterations=5

目的: 初期言語セットの魅力度と、第1世代の一貫性検証
調整対象:
  - 初期ペットの固有言語（8-12語）の感情的な響き
  - 接尾辞 -い, -た, -ね の自然な使用パターン
  - プレイヤーがその言葉を「かわいい」と感じるか

完了条件:
  - 初期言語が日本語の音韻体系に自然に聞こえる
  - 単独で会話させたときに、言語ブロック内での一貫性がある
  - 「このペット、独自の言葉を話している」と認識される

推定コスト: $3-5
所要時間: 15-25分
```

#### 中級（12回ループ）
```
コマンド: /ralph-loop --feature=language --level=intermediate --iterations=12 \
  --include-pair-conversation

目的: ペア会話での言語相互作用と、新しい語彙の自然な発生
調整対象:
  - 2ペット会話での接尾辞の交換・強化パターン
  - Hebbian ルール：同じ接尾辞が両ペットに出現したら、定着度+1
  - 複合語の創発条件（「めし」+ 「ほか」→ 「めし-ほか」など）

バランスチェック:
  - 会話から生まれた新語が過度に多くない（毎会話1語程度が自然）
  - 新語の論理性：親の言葉の組み合わせで説明できる
  - LanguageRebellion SubMolt の表示が視覚的に分かりやすい

完了条件:
  - 5世代連続プレイで、語彙が自然に増える様子がプレイヤーに見える
  - 新語の出現に一貫したルール感がある
  - 言語の個性化がペットの個性化と相関している

推定コスト: $6-10
所要時間: 40-60分
```

#### 上級（20回ループ）
```
コマンド: /ralph-loop --feature=language --level=advanced --iterations=20 \
  --include-generational-drift --include-rebellion-paths

目的: 複数世代の言語ドリフト。rebel-language スキルとの完全統合
調整対象:
  - 世代ごとの語順微変化（10世代で15-25%の語順シフト）
  - ダークルート（rebel-language）での言語反乱メカニズム
  - 帝国派（standard-language）と反乱派（rebel-language）の言語的対比

複雑性チェック:
  - SOV（標準）→ VSO（反乱）への段階的変化が説得力があるか
  - 音韻変化（接尾辞の誕生）と語順変化が独立しているか
  - 多言語コミュニティの形成：派閥ごとに言語が分化するか

完了条件:
  - 10世代以上のシミュレーションで、言語系統樹が生成される
  - プレイヤーが「言語を進化させる」のではなく「見守っている」感覚を得る
  - rebel-language スキルが、言語反乱シナリオを正確に検証できる

推定コスト: $14-22
所要時間: 80-120分
```

## 3. 交配システム (Breeding System)

### システム概要

`BreedingCircle` が管理する遺伝・交配メカニズム：
- **遺伝形質**：見た目（色、大きさ）、性格（活発性、社交性）、言語傾向（語彙スタイル）の継承
- **交配条件**：親密度（70%以上）、健康状態（50%以上）、環境整備（nest 存在）
- **双子・突然変異**：確率ベースの多様性導入（双子 5-8%、突然変異 2-3%）
- **Player Agency**：プレイヤーが意図的に形質を選別できる選択肢

### 交配システムの難しさ

**遺伝的説得力：**
- 単純なランダムでは、子が親と似ていないように見える
- Mendelian（メンデル式）的な継承を部分的に模倣する必要がある

**多様性の維持：**
- 同じペアを何度も交配させると、遺伝的多様性が低下
- 近親交配（inbreeding）の警告システムが必要

**Player Agency（P3 原則）：**
- プレイヤーが「この色のペット × この性格のペット」を意図的に選べるか
- ただしランダム性も残して、予測不可能な喜びを提供するか

### BreedingCircle SubMolt での可視化

```
[親1: アオペット（活発、社交的）] × [親2: アカペット（内向的）]
                ↓
    [誕生パーティクル: 赤紫色の光の渦]
                ↓
[子: アカペット（色）+ 活発性70% + 言語傾向=親1寄り）]

家系図表示:
├─ [親1] 世代1
│  └─ [子] 世代2 ← 親1の言語傾向を継承
└─ [親2] 世代1
```

プレイヤーはこの家系図を眺めることで、「この一族の個性」を感じられる。

### Ralph Loop 段階設定

#### 初級（5回ループ）
```
コマンド: /ralph-loop --feature=breeding --level=beginner --iterations=5

目的: 交配の基本フロー（親選択 → 交配判定 → 誕生）の検証
調整対象:
  - 交配条件の判定ロジック（親密度、健康度チェック）
  - 子ペットの基本情報生成（名前、色、初期ステータス）
  - 誕生演出（パーティクル、音、PetBook 自動投稿）

完了条件:
  - 2ペットの交配から子誕生まで、エラーなく完結
  - 子がプレイヤーのコントロール下に入る
  - 親子関係がセーブデータに正確に記録される

推定コスト: $2-4
所要時間: 15-25分
```

#### 中級（12回ループ）
```
コマンド: /ralph-loop --feature=breeding --level=intermediate --iterations=12 \
  --include-genetic-inheritance

目的: 親の形質が子に自然に受け継がれるシステムの構築
調整対象:
  - 色の継承ルール（メンデル式の簡略版）
  - 性格の継承（活発性スコアの平均 ± ランダム）
  - 言語傾向：親のコアボキャブラリ（8-10語）が子に70-90%の確率で出現

バランスチェック:
  - 子が親と「似ているが、全く同じではない」バランス
  - 複数世代の交配で、親の個性が薄まりすぎないか
  - PetBook での誕生投稿：「[親1] と [親2] の子が生まれました」が自然か

完了条件:
  - 3世代連続で、家系図が視覚的に分かりやすく表示される
  - 形質の継承パターンにプレイヤーが「規則性」を感じられる
  - 突然変異（例：青い親なのに赤い子）がプレイヤーを喜ばせる

推定コスト: $6-10
所要時間: 45-65分
```

#### 上級（20回ループ）
```
コマンド: /ralph-loop --feature=breeding --level=advanced --iterations=20 \
  --include-genetic-diversity --include-inbreeding-detection

目的: 多世代シミュレーションでの遺伝的多様性保全とプレイヤー選別
調整対象:
  - 近親交配の検出と警告（同じ遺伝子プール内の交配）
  - 遺伝的距離の可視化（家系図のUI）
  - Player Agency：「最適化選別」と「ランダム喜び」のバランス

複雑性チェック:
  - 5世代以上の家系図が、プレイヤーの手で「品種改良」可能か
  - AI コミュニティ内でも交配可能な仕組み（NPC ペットとの交配）
  - 遺伝的多様性が失われると、警告メッセージが表示されるか

完了条件:
  - 10世代シミュレーションで、形質の多様性が自然に維持される
  - プレイヤーが「この一族の色を固定したい」という意図を実行できる
  - 近親交配警告が、プレイヤーのゲームプレイに緊張感をもたらす
  - rebel-language スキルが、言語系統樹の遺伝的分岐を検証できる

推定コスト: $15-24
所要時間: 90-130分
```

## 統合バランス調整 (Ecosystem Harmony)

### 3システム統合ループ

```
コマンド: /ralph-loop --feature=ecosystem-harmony --iterations=25 \
  --lifedeath-weight=0.4 \
  --language-weight=0.35 \
  --breeding-weight=0.25

目的: 生き死に × 言語進化 × 交配の完全統合
シナリオ:
  1. 第1世代ペット2体を飼育開始
  2. 10ゲーム日でペア交配
  3. 第2世代誕生、親の言語継承を確認
  4. 第1世代が老化に向かい、死亡演出
  5. 追悼投稿が PetBook に掲載
  6. 第2世代が成長し、新しい言語を創発
  7. 第2世代と新規ペットの交配
  8. 多世代シミュレーション完成

検証ポイント:
  - 世代交代時の「別れ」と「新しい始まり」の心理的バランス
  - 言語が世代を超えて自然に伝承される
  - 家系図と言語系統樹が相関している
  - セーブデータ内で全3システムが正確に記録される
  - API コストが予算内（目標 $20-30 以内）

完了条件:
  - 複数のプレイテスター（5人以上）が「一族を育てている」という感覚を報告
  - 各システムの改善が他システムに負の影響を与えていない
  - 公式デモ用シナリオとして使用可能

推定コスト: $20-30
所要時間: 120-160分
```

## ベストプラクティス

### 初回実装時の推奨順序
1. **初級 × 生き死にシステム**（最も単純）
2. **初級 × 交配システム**（生き死にとの相乗効果）
3. **初級 × 言語進化**（最も複雑）
4. **中級ループは順序自由**（並列実行可能）
5. **統合ループは最後に**（すべてのシステムが安定してから）

### コスト管理のコツ
- 初級ループで5回に絞り、高速検証を優先
- 中級・上級ループは、初級で課題が見つかった項目のみ深掘り
- `--include-*` フラグは必要な場合のみ追加（コスト増）

### 質問テンプレート（ループ停止時）
```
「[システム名] が期待通りに動作していません。
- 現在の問題：[具体的な症状]
- 試したこと：[既にやったこと]
- 期待する動作：[目指す状態]

Ralph Loop を [初級/中級/上級] レベルで再実行してください」
```
