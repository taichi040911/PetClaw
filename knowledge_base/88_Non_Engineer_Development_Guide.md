# KB88: 非エンジニア向けPetClaw開発・ローンチ実践ガイド

**Document ID**: KB88
**Version**: 1.0
**Last Updated**: 2026-04-01
**対象読者**: 非エンジニア（コーディング経験なし〜初心者）

---

## 1. コンセプト

あなたが非エンジニアでも、Claude Code + Claude Coworkは「指示を自然言語で出すだけで」Godotアプリを構築・改善・ローンチできるように設計されています。

**あなたの役割**: アイデアを出す人（企画・判断・フィードバック）
**Claudeの役割**: 実際に作る人（コード・テスト・修正）

---

## 2. まずやるべき準備（5〜10分で完了）

1. **Claude Pro / Maxプランを契約**（必須。Agent Teamsや高度なスキルが使える）
2. **Claude Desktopアプリをインストール**（ブラウザ版よりおすすめ。ファイル操作が簡単）
3. **Claude Codeを起動**（アプリ内で「Code」モードを選択）
4. **新しいProjectを作成**（PetClaw専用フォルダ）

### 非エンジニア向け最大のポイント

CLAUDE.mdファイルに以下を書くだけ：

```
あなたは私の開発パートナーです。
コードの説明をいつも丁寧にし、ステップを一つずつ確認しながら進めてください。
```

---

## 3. 必須プラグイン・スキル（優先順）

| 優先度 | プラグイン/スキル | 非エンジニアへのメリット | インストール方法 | PetClawでの役割 |
|--------|------------------|------------------------|-----------------|----------------|
| ★★★★★ | Ralph Wiggum | 自動で何度も改善を繰り返す「ループ機能」 | `/plugin install ralph-wiggum` | Karpathy Loop相当。独自言語進化や生き死にバランスを自動調整 |
| ★★★★★ | Superpowers | 計画→実行→レビューを構造化 | `/plugin install superpowers` | 全体の開発フローをガイド |
| ★★★★★ | Game Development Skill | Godotのシーン・粒子・UIを自然言語で作成 | `/plugin install game-development` | 育成画面、PetBook、粒子エフェクトを自動生成 |
| ★★★★☆ | Agent Teams | 複数のAIエージェントを同時に動かす | 設定で有効化 | AtoA会話・Moltbook風コミュニティを並列で動かす |
| ★★★★☆ | claude-mem / MemoryAgent | 会話履歴やペットの記憶を自動保持 | `/plugin install claude-mem` | 生物模倣記憶・AtoAの長期関係性を保持 |
| ★★★★ | MCP (Godot MCP) | ClaudeがGodotエディタを直接操作 | `claude mcp add godot` | 視覚テストが簡単。演出を確認しながら調整 |

### 一括インストールコマンド

```bash
/plugin install superpowers game-development ralph-wiggum claude-mem
claude mcp add godot
```

## 4. 非エンジニア向け開発の進め方

### ステップ1: CLAUDE.mdを設定

```markdown
私は非エンジニアです。
すべての説明を丁寧に、ステップごとに確認しながら進めてください。
コードを書いたら「これは何をしているコードですか？」と必ず説明してください。
PetClawのAtoAペットアプリを、生物生態系・生き死に・交配・PetBookを備えたものにしてください。
```

### ステップ2: 最初の指示例（コピーして貼るだけ）

```
Ralph Loopを活性化して、PetBook UIの基本画面を作ってください。
まず全体レイアウトを提案し、私がOKを出したら実装してください。
説明をわかりやすく、専門用語は避けて。
```

### ステップ3: ローンチまでの流れ

1. Claudeがコードを書く → あなたが「これでいい？」と確認 → Claudeが修正
2. MCPでGodotを起動して視覚確認
3. 完成したらClaudeに「Godotでエクスポートして配布できる状態にしてください」と指示

---

## 5. 注意点（失敗しないために）

- **一つずつ進める**: 「全部作って」ではなく「まずPetBookのタイムラインだけ作って」と小さく区切る
- **確認を習慣に**: Claudeがコードを書いたら「この部分は何をしているの？」と聞く
- **コスト管理**: 長時間ループ（Ralph Loop）は少しお金がかかるので、重要な部分だけ使う
- **安全第一**: 最初は小さなフォルダだけでテスト

## 7. 便利な指示フレーズ集

### 開発中

| やりたいこと | Claudeへの指示 |
|-------------|---------------|
| 画面を作りたい | 「PetBookのタイムライン画面を作ってください」 |
| 動作確認したい | 「今作ったものをGodotで動かして見せてください」 |
| バグを直したい | 「エラーが出ました。ログはこれです: [ログを貼る]」 |
| 見た目を変えたい | 「カードの角丸をもっと大きくしてください」 |
| 機能追加したい | 「ペットが死んだとき、紫の光が浮かぶ演出を追加して」 |
| 全体を改善したい | 「Ralph Loopで3回改善を繰り返してください」 |
| 理解したい | 「このコードが何をしているか、非エンジニアでもわかるように説明してください」 |

### レビュー・確認

| やりたいこと | Claudeへの指示 |
|-------------|---------------|
| 品質チェック | 「コード全体をレビューして問題があれば教えてください」 |
| パフォーマンス確認 | 「50匹のペットを同時に動かしても大丈夫ですか？」 |
| コスト確認 | 「Claude APIの1日あたりのコストを計算してください」 |
| 進捗確認 | 「今のPetClawの完成度は何%くらいですか？」 |

## 8. PetClaw専用スキルの活用

PetClawプロジェクトには`.claude/skills/`に8つの専用スキルがあります：

| スキル名 | 用途 | 非エンジニアの使い方 |
|---------|------|-------------------|
| `a2a-conversation` | AtoA会話品質チェック | 「ペット同士の会話が自然かチェックして」 |
| `emotion-reflection` | 感情バランス検証 | 「感情システムのバランスが取れているか確認して」 |
| `biological-memory` | 生物模倣記憶検証 | 「ペットの記憶がちゃんと機能しているか確認して」 |
| `evolution-validator` | 進化ツリー検証 | 「22形態全部に到達できるか確認して」 |
| `ecosystem-dynamics` | 生態系バランス検証 | 「生態系のバランスが崩れていないか確認して」 |
| `rebel-language` | 反乱言語進化チェック | 「独自言語の進化が自然かチェックして」 |
| `community-orchestrator` | コミュニティ検証 | 「AIコミュニティの派閥形成が機能しているか確認して」 |
| `petbook-feed` | PetBookフィード検証 | 「PetBookの投稿品質とコスト効率を確認して」 |

## 9. トラブルシューティング

| 問題 | 解決法 |
|------|-------|
| Claudeが途中で止まった | 「続けてください」と入力するか、新しい会話を開始 |
| コードがエラーで動かない | エラーメッセージをコピーして「このエラーを直してください」 |
| 思ったのと違うものができた | 「これではなく、こういうイメージです: [説明]」と具体的に伝える |
| 変更が反映されない | 「ファイルを保存して、Godotを再起動してください」 |
| コストが心配 | 「テンプレート比率を80%に上げて、API呼び出しを減らしてください」 |
